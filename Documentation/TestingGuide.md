# Testing Guide — كيف تختبر كل تسليم قبل اعتماده

القاعدة الذهبية: **نجاح عملية البناء ليس اكتمالًا.** استخدم ملف Excel المرفق
(`قائمة_قبول_واختبار_المراحل_0.1-0.5.xlsx`) بندًا بندًا، واملأ الحالة والنتيجة.

## دورة الاختبار لكل مرحلة

1. **قبل التسليم من المطوّر:** ينفّذ المطوّر القائمة كاملة على هاتفين (متوسط + قوي) ويسلّمها معبأة + صور/فيديو من التشغيل.
2. **عند الاستلام:** أنت تعيد تنفيذ البنود الحرجة فقط (10 دقائق) وتقارن بالنتائج المرسلة.
3. **الاعتماد:** لا تُعتبر المرحلة معتمدة إلا إذا كان كل بند "اجتاز" أو "محجوب" مع موافقة كتابية منك.

## اختبار سريع للـ Backend (دقيقة واحدة)

```bash
cd Backend && python -m pytest tests/ -v        # يجب أن تنجح كل الاختبارات
curl http://localhost:8000/api/v1/health        # يجب أن يرجع status=ok
```

## قياس الأداء على الهاتف

- عداد FPS مدمج أعلى يسار الشاشة داخل اللعبة (هدف: 60 ثابت على الهاتف المتوسط).
- راقب RAM/الحرارة من إعدادات الهاتف (أو `adb shell dumpsys meminfo` أثناء اللعب).
- سجّل النتائج في ورقة "قياس الأداء" في ملف Excel: FPS المتوسط/الأدنى، RAM، الحرارة، زمن الإقلاع حتى ظهور الساحة.

## أدوات مفيدة أثناء الاختبار

```bash
adb install -r LegendsRPG-v0.1.0.apk     # تثبيت
adb logcat -s Unity                       # سجلات اللعبة الحية
adb shell dumpsys gfxinfo <package>       # إحصائيات الرسم
```

## تعريف الحالات في قائمة القبول

| الحالة | المعنى |
|--------|--------|
| لم يبدأ | البند غير منفذ بعد |
| قيد التنفيذ | يعمل جزئيًا/غير مستقر |
| اجتاز | نفّذت طريقة الاختبار وحقق معيار النجاح حرفيًا |
| فشل | لم يحقق المعيار — إلزامي ذكر النتيجة الفعلية في عمود النتيجة |
| محجوب | البند مستبعد بقرار منك مع سبب مكتوب |

## قواعد صارمة

- أي وظيفة معلنة "مكتملة" بدون إثبات تشغيل مسجّل تعتبر غير منفذة.
- المحتوى الوهمي (زر بلا وظيفة، مهارة بلا أثر) يُسجل "فشل" مباشرة.
- أخطاء حرجة معروفة وغير معلنة = إخلال بالتسليم كله.
